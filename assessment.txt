1. Project Overview & Objective
This comprehensive practical assessment requires you to synthesize and apply all core Laravel concepts
covered during our coursework. You will build a fully functional, database-driven web application named 
"Enterprise Resource & Project Manager" (ERPM) from scratch. This project tests your mastery of routing,
database migrations, seeders, factories, eloquent relationships, authentication mechanisms, middleware
protection, layout templating with Blade directives, full CRUD operations (both Blade-rendered views and a
JSON REST API), and transactional email notifications using Google App Passwords.
2. Core Technical Requirements
A. Database Architecture & Seeders
Your database schema must be robust, properly normalized, and populated using Laravel seeders and
factories:
Migrations: Create clean migration files with proper foreign key constraints, indexes, and onDelete
cascading rules where appropriate.
Factories & Seeders: Use Laravel Model Factories and Faker to generate realistic dummy data. Each
table must be seedable with at least 15–20 realistic records.
Database Seeder: Ensure DatabaseSeeder orchestrates the seeding order correctly without constraint
violation errors.

B. Eloquent Relationships (Mandatory Implementations)
Your models must implement and demonstrate the following four relationship types:
One-to-OneUser & Profile: Each user has one extended profile (bio, phone, avatar, social links).
One-to-ManyDepartment & Employees / Project & Tasks: A department houses many employees, and
a project contains many tasks.
Many-to-OneTask & Assigned User: Many tasks belong to a single assigned user.
Many-to-ManyProject & Skills / Employees & Trainings: Projects require multiple skills, and skills apply
to multiple projects (with pivot table timestamps and extra attributes).
C. Authentication & Middleware Security
Secure your application using dual authentication layers:
Custom Authentication: Implement at least one custom auth controller handling manual credential
verification, session regeneration, and secure logout.
Laravel Breeze Integration: Integrate Laravel Breeze for robust user registration, login, email verification,
and password reset flows.
Middleware Protection: Explicitly apply and customize auth and guest middlewares across your web
routes to restrict unauthorized dashboard access and prevent logged-in users from hitting login/register
pages.
D. Layouts, Views & Blade Directives
Build a clean, responsive frontend interface:
Layout Inheritance: Create a master layout file (e.g., layouts.app) featuring dynamic header/footer
slots, navigation bars, and flash message containers.
Blade Directives: Utilize directives such as @extends, @section, @include, @if / @auth, @foreach,
and component slots effectively to keep templates DRY (Don't Repeat Yourself).
E. CRUD Operations (Blade Views & REST API)
Implement dual-interface data management for your primary resource (e.g., Projects or Tasks):
Web CRUD: Full Create, Read, Update, and Delete capabilities rendered via Blade views with form
request validation and success/error flash notifications.
API CRUD: A fully functional JSON API version protected by API tokens or Sanctum (or standard resource
controllers returning JSON responses with proper HTTP status codes 200, 201, 404, 422).

F. Mailer & Google App Password Integration
Configure Laravel's mail subsystem to dispatch real emails:
Configuration: Configure config/mail.php and .env using SMTP credentials paired with a generated 
Google App Password.
Mailable Class: Create a custom Mailable class (e.g., WelcomeNewUserNotification or 
ProjectAssignedNotification ) featuring a clean Markdown or Blade HTML view.
Trigger: Automatically dispatch this email whenever a new user registers or is assigned to a high-priority
project.
